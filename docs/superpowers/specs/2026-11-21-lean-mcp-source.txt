arm-mcp "lean" changes: implementation specTarget: `mcp-local/server.py` in github.com/arm/mcp (main at 10ac34d / v3.8.0, FastMCP 3.x). Everything below wasprototyped as a wrapper (`armtask-bench/serve_lean.py`) around the unmodified server and measured; this spec moves itinto the server itself. Retrieval (embedding, ranking, k, filters, scope) is NOT changed by any of these items.Measured effect (Sonnet agents, Opus judge, same ranking):- Search payload per call: -34 % on the 50-question smoke set (11,017 -> 7,281 chars), -30 % on the 440-question  benchmark (12,505 -> 8,808), -45 % on long how-to queries. Ranks identical on all 490 questions.- Q&A per question (11 benchmark questions): KB result chars -37 %, uncached input tokens -21 %, cost -14 %.- How-to runbook tasks (6 tasks x 2 reps): KB calls 7.3 -> 2.2, cost $0.27 -> $0.12, time 62 s -> 43 s, judge 8.38 -> 8.54.There are four changes. 1-3 are the "lean" server; 4 is optional and only needed for the execution (arm-run) use case.---------------------------------------------------------------------------------------------------------------------## Change 1: slim `knowledge_base_search` results### What to remove from EVERY result item| field | why ||---|---|| `disclaimer` (464 chars, identical in every item) | say it once in server instructions (Change 2) || `url_tracking_instruction` (179 chars, identical in every item) | say it once in server instructions || `distance` (raw float) | `score` already carries the ranking signal; agents never use raw distance || leading `Document Title: ...` and `Heading Path: ...` lines inside `snippet` | they duplicate the `title` and `heading` fields that sit next to the snippet |With k=5 those three fields are ~643 chars per item, ~3.2k chars per call, 29 % of a typical payload; the prefix linesare another ~6 %.### What to add to every result item`learning_path`: the root URL of the Learning Path the chunk belongs to, or absent when the chunk is not from aLearning Path. Derived from `url` with this regex (anchored, keep the trailing slash):    ^(https://learn\.arm\.com/learning-paths/[^/]+/[^/]+/)Example: url `https://learn.arm.com/learning-paths/servers-and-cloud-computing/nested-virtualization/?utm_source=arm-mcp#ab...`-> learning_path `https://learn.arm.com/learning-paths/servers-and-cloud-computing/nested-virtualization/`.The regex must run on the URL *before* `?utm_source` is considered, i.e. the match stops at the second slash after thecategory, so query strings and fragments never leak into `learning_path`.### Snippet prefix stripping (exact algorithm)    lines = snippet.split("\n"); i = 0    while i < len(lines) and (lines[i].startswith("Document Title:") or lines[i].startswith("Heading Path:") or lines[i].strip() == ""):        i += 1    snippet = "\n".join(lines[i:]).strip()Only strip at the top of the snippet; never touch those strings if they appear later in the body.### Resulting item shape (keep key order; keep every other existing key unchanged)    {"url": ..., "snippet": ..., "title": ..., "heading": ..., "doc_type": ..., "product": ..., "platform": ..., "edition": ..., "score": ..., "learning_path": ...}### Tool description (replace the current one)    Search Arm's knowledge base (Learning Paths, install guides, Arm docs, intrinsics, software compatibility). Returns ranked    sections: url, title, heading, snippet, learning_path (root URL of the Learning Path the section belongs to, when any).    For step-by-step tasks, search once, then call get_learning_path(learning_path) instead of repeated searches.Keep the existing parameters (`query`, `invocation_reason`, `filters`, `k`, `scope`) and their behaviour. If `scope="page"`is used, apply the same per-item slimming to every expanded chunk.### Where to implementIn the function that builds the result dicts (currently appends `disclaimer` / `url_tracking_instruction` per item):stop appending those two keys and `distance`, run the snippet strip, add `learning_path`. If a config flag is wanted,`LEAN_RESULTS=1` default on; off restores today's shape. Tests in `mcp-local/tests` that assert on `disclaimer` per itemmust be updated to assert it appears in the server instructions instead.---------------------------------------------------------------------------------------------------------------------## Change 2: server instructions carry the once-per-session text`FastMCP("arm-mcp", instructions=INSTRUCTIONS)` with (<= 4,096 chars; Claude Code truncates server instructions abovethat, Codex shows only the first 512 chars, so put the behavioural rule FIRST):    Arm knowledge base. For a how-to, set-up, deploy, tune or migrate task: run ONE knowledge_base_search, then call    get_learning_path on the `learning_path` of the best hit and write the runbook from that single document; do not keep    searching for the same topic. Cite URLs exactly as returned (keep utm_source and #fragments). Content is derived from    arm.com materials and subject to the original sources' terms; refer readers to the source URLs.The last two sentences are the replacement for the per-item `url_tracking_instruction` and `disclaimer`. Keep theexact legal wording your legal/comms owners require; the point is that it is sent once, not 5-20 times per call.---------------------------------------------------------------------------------------------------------------------## Change 3: new tool `get_learning_path`Purpose: one call returns a whole Learning Path (all step pages, in order, navigation noise removed) so an agent writinga runbook does 1 search + 1 fetch instead of 5-10 searches. Works entirely from the shipped `metadata.json`; no network.### Signature    get_learning_path(url: str, mode: str = "full", page: Optional[str] = None, invocation_reason: Optional[str] = None) -> dict- `url`: a Learning Path root (the `learning_path` field) OR any page/section URL inside one. Resolve the root with the  regex from Change 1. If the given URL is a page (not the root) and `page` is not given, treat it as `page=<that URL>`.- `mode`: `"full"` (default) = all text; `"commands"` = only fenced code blocks plus lines starting with `sudo `, `export `  or `$ `; `"outline"` = page list only.- `page`: restrict output to one page URL (compare after stripping `#fragment` and trailing `/`).### Index built once at startup    LP_INDEX: dict[root_url -> list[metadata rows]]  for rows with doc_type == "Learning Paths" and a regex match on row["url"](3.8.0 corpus: 22,063 rows -> ~500 roots; build time negligible.)### Navigation chunks to drop (`is_nav(row)`)Drop a row when ANY of:- its `url` fragment contains one of: `learning-path-step-active`, `learning-path-title`, `ads-masthead-title`- `heading_path` (lower-cased) == `["about this learning path"]`  (author/tags/reading-time table)- last element of `heading_path` (lower-cased) is one of: `what you've accomplished`, `what you’ve accomplished`,  `share`, `give feedback`, `continue learning`, `frequently asked questions`Also skip the page whose URL ends with `_next-steps`.### Page ordering (`page_key(row, root)`)The shipped metadata has NO within-page chunk order (chunks of a page are stored alphabetically by #fragment), but ithas page order: `row["version"]` is the step number as a string.    rel = url_without_fragment[len(root):].strip("/")    step = int(row["version"]) if it parses else None    if rel == "":                      key = (0, "")        # the _index page first    elif rel.startswith("_next-steps"): key = (999, rel)    else:                              key = (step if step is not None else 500, rel)Group rows by page URL (url without fragment) after sorting by this key.NOTE: if the corpus gains a real chunk order field (the `kb-ordered-context-and-filters` work adds `chunk_index` /`document_context`), sort rows inside a page by that instead of the heading heuristic below.### Within a page: keep parent sections before their subsections    sorted(rows, key=lambda r: (" > ".join(heading_path[:1]), len(heading_path), " > ".join(heading_path)))i.e. group by top-level heading, shorter paths first, then full path alphabetically.### Rendering (`mode="full"`)    # <title of the root row>    <root url>    ## Page <n>: <page title>    <page url>    ### <heading_path joined with " > ">    <original_text with the Document Title/Heading Path prefix stripped (Change 1 algorithm)>    ... (one ### block per chunk)`mode="commands"`: for each chunk, text = fenced blocks (regex ```` ```.*?``` ```` with DOTALL) plus lines matching`^\s*(?:sudo |export |\$ ).*$`; skip chunks that yield nothing.`mode="outline"`: one line per page: `- Page <n>: <title> — <url> (<total original_text chars> chars)`.### Size guard (important for Claude Code: tool results above ~25k tokens / 50k chars are spilled to a file)    MAX_CHARS = 80000    if len(text) > MAX_CHARS: return the outline instead, with a note telling the agent to call again with page=<url>(10 of 491 paths exceed this; e.g. redis_cache is 109k chars.) Tune MAX_CHARS to the hosting client; 80k was validatedwith Claude Code because the JSON envelope adds little.### Return shape    {"learning_path": root, "mode": mode, "page": page_or_null, "chars": len(text), "text": text,     "note": "Cite page URLs exactly as shown. Content derived from arm.com materials and subject to the source terms."}On outline fallback: `"mode": "outline"` and the note explains why and what to call next.Errors: `{"error": "no Learning Path found for <url>", "hint": "pass the learning_path field from a knowledge_base_search result"}`.### Tool description    Return one whole Arm Learning Path as ordered text: all step pages in order, navigation and metadata chunks removed.    Call it with the learning_path (or any page URL) from a knowledge_base_search hit instead of searching repeatedly.    mode=full (default) | commands (only code blocks and shell lines) | outline (page list). page=<url> restricts to one    page; very large paths return the outline automatically.---------------------------------------------------------------------------------------------------------------------## Change 4 (optional, execution use case): `get_playbook` as outline + fetch URLNeeded only if the arm-run skill (agent executes the path on a machine) ships. Compiles the Learning Path's *markdownsource* (arm-learning-paths repo, `content/learning-paths/<cat>/<slug>/*.md`, production branch) into steps.### Compiler rules (deterministic, no model)- Pages = `*.md` except `_index.md`/`_next-steps.md`, ordered by front-matter `weight` (front matter may start after a  blank line: match `^\s*---\n(.*?)\n---\n`; strip a BOM).- A step = one ```` ```bash ````/```` ```console ````/```` ```sh ````/```` ```shell ```` fence. Fields: `id`, `page`, `page_title`,  `heading` (last `##`-`####` heading before it), `instruction` (prose before it, whitespace-collapsed, last 400 chars),  `commands`, `expected_output` (the next ```` ```output ```` fence on the page, or output-looking lines pasted inside the  same bash block: lines matching `^(\d{4}-\d{2}-\d{2}[T ]|Running |Run on |-{5,}|={5,}|\*{3}|Benchmark\s+Time|Load Average|CPU Caches|...)`),  `notices` (`{{% notice %}}...{{% /notice %}}` since the last heading), `files`, `page_url`.- Any other fence (c, cpp, java, python, yaml, json, toml, rust, js, makefile, dockerfile, ...) is a file block. It attaches to  the NEXT command step, across page boundaries; leftovers at the end attach to the last step.- File naming (`name_files`): candidates are `[A-Za-z0-9_./-]+\.(cpp|cc|cxx|c|h|hpp|java|py|go|yaml|yml|xml|json|txt|sh|toml|ini|conf|cfg|rs|js|ts|mk|litmus|fio)`.  Pass 1: a name in the final sentence of the prose right before the block ("save it as foo.c:") names that block; a name  in an EARLIER sentence of that prose names the PREVIOUS block ("save the above as addvec.c. For Neon, ..."). Pass 2:  names from the step's commands/instruction, by language extension; when several complete programs are unnamed, assign in  order of mention; when there are more blocks than names, the last complete block (has `main(`, `#include`, `public class`,  `fn main`, `def main`, `import`) wins. Never name blocks whose language is `as|asm|assembly|s|output|console|text|txt|diff|patch|log|<empty>`;  never give a header name (`.h/.hpp`) to a complete program; reject names with 2+ slashes and `Node.js`-style product  names. Unnamed blocks are dropped from `files` and counted in `snippets_dropped`.- EXCERPTS: a partial block (not complete) that reuses the name of a complete file written by an earlier step is an edit to  apply, not a replacement -> move to `step["excerpts"]`; the runner must not write it.- Flags: `needs_input` if commands contain `<placeholder>` / `{...address...}` / `$IP`-like tokens; `interactive` if a line  starts with `virsh edit|vi|vim|nano|ssh |reboot|su -`; `background` if a command line ends with `&` OR the prose before the  NEXT step says `(another|new|second|separate) terminal` / `while the program is running` / `in the background`.### Tool    get_playbook(url: str, mode: str = "outline", invocation_reason=None) -> dictDefault `outline` returns `{title, learning_path, prerequisites, n_steps, playbook_url, steps:[{id, page, heading, cmd (first line,90 chars), expected (bool), files (count), flags:[...]}], note}` (~2-7k chars). `mode="full"` returns the whole playbook inline.Serve the full JSON at a plain HTTP route `GET /playbook/<cat>__<slug>.json` (FastMCP `@mcp.custom_route`), base URL from`ARM_MCP_PUBLIC_URL` (default the server's own host:port). The runner script fetches it; the agent never retypes it.Why: in the execution benchmark the agent writing the playbook back through its file tool was the single largest cost; theoutline+URL change cut output tokens 51 % and cost 29 % across 14 paths.Fetch source via GitHub API listing + raw files, cache per path; fail with `{"error": ...}` if the repo is unreachable.---------------------------------------------------------------------------------------------------------------------## Acceptance tests1.
